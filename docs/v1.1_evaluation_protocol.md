# PredicateLab V1.1 evaluation protocol

This document defines the protocol the V1.1 code enforces.  It is normative:
if an execution cannot satisfy a rule here, it must fail closed rather than
emit a warning and continue.

## 1. Non-negotiable boundaries for this phase

* No new real TSIL final evaluation.  The historical 2024-01-01 .. 2025-08-31
  holdout was already read once; it stays consumed.  Widening a run window so
  that it re-reads those dates is also forbidden.
* No paper-scale experiment and no new LLM, mineral or image adapter.
* The TSIL native loss, the 23 upstream predicates, the six temporal
  predicates and the upstream `Predicate_Gen` behaviour are unchanged.
* Every fix is preceded by a test that reproduces the defect; every scientific
  outcome is labelled `VERIFIED`, `CODE_ONLY`, `NOT_VERIFIED` or `FAILED`.

## 2. Lifecycle

```
discover  ──▶ freeze-family ──▶ confirm ──▶ finalize
(search)      (frozen family)    (new data /   (one-time
                                  disjoint      holdout, ledger
                                  resamples)    guarded)
```

`discover` may create additional rounds and may be resumed.  `freeze-family`
records the exact member set, template hashes, discovery evidence ids and
effect estimates.  `confirm` evaluates only that set, on folds that were not
visible to the generator.  `finalize` requires both a `search_complete` run
and confirmation evidence whose state is `independently_confirmed` or
`resampling_confirmed`.

### 2.1 Run and round state machines

Run statuses: `running` → `search_complete` → `confirmation_complete` →
`final_complete`.  Failure paths are `interrupted`, `failed` and `final_failed`.
A round is `running` while it executes; only after evidence, feedback and the
round status are committed in one transaction does it become `completed`.  A
crash leaves it `running`/`interrupted`, which is resumable and never counts as
a completed round.

The candidate generator's proposals for a round are persisted in the round
summary.  On resume the engine re-validates those exact templates instead of
asking the generator for a new set, so an interrupted round cannot invent new
candidates and cannot double-count evidence.

### 2.2 Atomicity and cache validity

* Trial rows are upserted keyed by
  `(candidate_id, fold_id, protocol_hash, config_hash)`.
* `config_hash` covers the complete experiment identity: data snapshot and full
  content manifest, label expression and label-spec hash, fold dates/role/
  phase, seed, model specification, training budget, preprocessing version,
  code fingerprint and environment versions.
* Work directories are phase-, fold- and seed-isolated.  A path from another
  phase cannot be mistaken for this phase's output.
* The persisted content-manifest cache is accepted only if its own
  `manifest_hash` validates against its payload; a tampered cache is rebuilt.
* A trial whose prediction file is missing, whose stored result digest does not
  match, or whose phase is unknown is not trusted for reuse.
* Results with NaN/Inf are sanitised to `null` and listed under `null_paths`;
  they are never stored as a finite success.  A worker that exits non-zero is
  `failed` even if a fresh-looking `result.json` exists.  Malformed or
  non-finite results are `failed`.

### 2.3 Coverage and missing folds

Aggregation tracks expected versus executed folds.  A candidate whose executed
fold coverage falls below `min_fold_coverage` is `insufficient`, even if the
folds that did run look strong.  A failed fold is recorded in the reason; it is
never silently dropped.  Multi-seed runs require the configured seeds to
execute; seed agreement is reported separately from fold stability.

## 3. Holdout: a consumable, globally keyed resource

### 3.1 Identity

```
holdout_key = SHA256(
    dataset_id, snapshot_hash, data_manifest_hash,
    label_spec_hash, test_start, test_end
)
```

`run_id`, `study_id`, `candidate_id`, protocol hash, manifest timestamp and
artifact path are deliberately absent.  Changing any of them cannot mint a new
confirmatory access.

### 3.2 Claim semantics

The claim runs inside `BEGIN IMMEDIATE`; SQLite's partial unique index over
active statuses makes the race atomic.  Statuses:

```
intent → claimed → running → completed
                        ↘ failed
                        ↘ interrupted
```

* `claimed`, `running`, `completed`, `failed` and `interrupted` are all
  **consumed**: the data may already have been observed.
* Only a retry of the exact same `(run_id, candidate_id, manifest_hash)`
  reuses the row.  A retry of an already `completed` access returns the saved
  result and records no second claim.
* Any other run or candidate gets `HoldoutConsumed`.
* A crash counts as consumption.  Restarting the same experiment resumes the
  same claim; it does not arm a second test.
* `exploratory_reuse` rows are recorded separately, are never confirmatory and
  cannot be counted as fresh evidence.

### 3.3 Period-level guard

Snapshot identity can change legitimately (V1.0 sampled hashes versus V1.1 full
content manifests) and historical rows can have unprovable identity.  Therefore,
after the exact-key lookup, a second guard rejects any claim on the same
`dataset_id` whose test window overlaps an existing consumed row.  A historical
row with `test_start`/`test_end = legacy_unknown` matches every window and
fails closed.  A non-overlapping window on the same dataset is allowed.

For static tabular data the protocol has no dates, so the window is empty and
the period guard cannot add protection; identity there rests on the snapshot
hash of the full feature matrix and labels.  This is recorded as a residual
risk, not hidden.

### 3.4 Historical backfill

`predicatelab.cli migrate --db ... --backfill-artifacts artifacts` scans
historical `context.json` / `final_evaluation.json`.  Provable fields are
filled; unprovable fields are set to `legacy_unknown` and listed under
`missing_fields`.  A backfilled row is `origin=backfill_legacy` and is
`completed/consumed`; it is never relabelled as a V1.1 confirmatory run.

## 4. Label-dependency time isolation

The label is `Ref($close, -2) / Ref($close, -1) - 1`.  Its value at date `t`
needs the close at the next two **trading** days, not two calendar days.

The engine:

1. parses the label expression and the data contract's declared
   `future_offset_trading_days`; a mismatch raises `LabelDependencyError`;
2. reads the real trading calendar from the adapter (qlib
   `calendars/day.txt` for TSIL);
3. trims the train, validation and test tails whose label is not yet
   available — the trimmed end is written into the effective fold, not merely
   reported;
4. requires `purge_days > 0` for label-dependent folds; `purge_days=0` is a
   hard error;
5. records the number of `(instrument, date)` label values that would leak
   across the declared boundary.

2023 year-end is the concrete regression case: 2023-12-28 needs 2024-01-02 and
2023-12-29 needs 2024-01-03.  Each date has 300 CSI300 instruments, so the exact
count is **600 leaked sample-dates** (314 distinct instruments in the union).
The test `tests/test_adversarial_label_isolation.py` asserts this against the
real qlib calendar and data.

A validation segment that reaches into the holdout dates is a hard error, not
a warning.

## 5. Discovery, confirmation and final are not interchangeable

| stage | data | may feed the generator? | claim licence |
|---|---|---|---|
| discovery | search folds (2020–2022 TSIL) | yes | `exploratory_positive` |
| confirmation | later data (2023) or disjoint resamples | no | `independently_confirmed` (time-forward) / `resampling_confirmed` (resamples) |
| final | frozen holdout (2024–2025) | no | one-time, ledger-guarded |

Confirmation on extra CV repeats of the same pool is explicitly
`resampling_confirmed`: it is not new data and cannot be reported as independent
replication.  The final result is a separate record and is never fed back.

### 5.1 Candidate states

`executable`, `exploratory_positive`, `resampling_confirmed`,
`independently_confirmed`, `insufficient`, `rejected`, `legacy_unknown`.

`validated` remains a mechanical evidence status ("passed the pre-registered
bar at this stage").  It is not a scientific claim.  Historical rows that
cannot be proven are `legacy_unknown`; no automatic relabelling is performed.

## 6. Statistics

For each promoted candidate the engine computes the paired difference
(candidate − baseline) on common units:

* **effect** — mean paired difference; direction is applied explicitly so a
  lower-is-better metric (log-loss) treats a negative difference as an
  improvement;
* **uncertainty** — moving-block bootstrap CI and Newey–West HAC standard
  error; time-series and fold and seed components are reported separately
  (`time_series_ci`, `fold_effect_sd`, `seed_effect_sd`);
* **p-value** — two-sided normal approximation of `effect / HAC_SE` where the
  design supports it;
* **q-value** — Benjamini–Hochberg over the tested family at that stage;
* **stability** — fraction of folds with the pre-registered sign;
* **coverage** — executed/expected folds; **seed agreement** — fraction of
  seeds with the expected sign.

A single-point holdout has no estimable SD.  Its CI and p-value are `null`
(listed in `null_paths`), and its state is `insufficient`.  It cannot be
presented as a significant result.  This is deliberate: an undefined statistic
must not become 0 or NaN.

## 7. Evidence bundle

`predicatelab.cli export` writes:

| file | content |
|---|---|
| `context.json` | task, data contract, snapshot, full manifest hash, label isolation, effective folds, policy, code/environment |
| `report.json`, `report.md` | evidence counts and human-readable report |
| `evidence.jsonl`, `evidence.json` | every evidence row, including failures |
| `frozen_family.json` | exact frozen member set |
| `frozen_manifest.json` | finalization manifest (pre-final snapshot) |
| `confirmation.json` | confirmation results |
| `final_evaluation.json` | final result, states, null paths |
| `holdout_access.json` | ledger rows for this run |
| `trials.json` | per-trial records with phase, seed, config hash, result hash |
| `predictions/*.npz` | score, label, sample/date index where the adapter emits it |
| `checksums.sha256` | SHA-256 of every content file |
| `bundle_manifest.json` | file list, prediction counts, `bundle_hash` |

Trials whose adapter did not emit predictions are counted under
`predictions.n_missing`; empty or directory prediction paths are skipped, never
copied.  TSIL writes `instrument`, `date`, `score` and `label` arrays.
Tabular writes `sample`, `score` and `label` (it has no time axis).

## 8. Commands

```bash
PY=/home/dmz-ai/miniconda3/envs/zzr_py312/bin/python
DB=artifacts/predicatelab.sqlite

$PY -m predicatelab.cli validate-config --config configs/tsil_lstm_smoke.yaml
$PY -m predicatelab.cli discover      --config ... --rounds 1
$PY -m predicatelab.cli freeze-family --config ... --run-id run_... [--candidate-id ...]
$PY -m predicatelab.cli confirm       --config ... --run-id run_...
$PY -m predicatelab.cli finalize      --config ... --run-id run_... --candidate-id cand_...
$PY -m predicatelab.cli export        --config ... --run-id run_... --out .../bundle
$PY -m predicatelab.cli migrate       --db $DB --backfill-artifacts artifacts
$PY -m predicatelab.cli holdout-audit --db $DB
$PY -m predicatelab.cli evidence      --config ... --run-id run_...
```

`migrate` is additive and idempotent.  `holdout-audit` lists the global ledger;
it never reads data.

## 9. What V1.1 does not claim

* No new real TSIL final result exists.  Historical 2024–2025 numbers remain
  historical, with an unverifiable isolation status, and are not republished as
  V1.1 evidence.
* No paper-scale TSIL V1.1 discovery/confirmation has been executed.  The TSIL
  V1.1 path is code- and unit-tested, and its configs validate, but is
  `CODE_ONLY` until such a run is approved.
* Resampling confirmation is not independent replication.
