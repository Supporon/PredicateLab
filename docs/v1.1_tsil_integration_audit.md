### 3.1 P0 缺陷卡

#### D-01 [历史 A] TSIL 快照身份每次调用都变化

- **位置**：`predicatelab/domains/tsil/adapter.py:111-151`（`snapshot`），关键行 `133`；`predicatelab/core/engine.py:319-328`；`predicatelab/core/schema.py:157-171`。
- **触发**：对同一份未变数据连续调用两次 `TSILAdapter.snapshot()`；或对已存在的 TSIL run 再次构造 `PredicateLabEngine(...).run()/freeze_family()/confirm()/report()`。
- **最小复现**：

```bash
PYTHONPATH=. /home/dmz-ai/miniconda3/envs/zzr_py312/bin/python \
  artifacts/audit_v11/probes/repro_A_snapshot_identity.py
PYTHONPATH=. /home/dmz-ai/miniconda3/envs/zzr_py312/bin/python \
  artifacts/audit_v11/probes/repro_A_engine_resume.py
```

实际输出（`artifacts/audit_v11/logs/repro_A.log`、`repro_A2.log`）：

```
{"merkle_equal": true, "generated_at_equal": false, "manifest_hash_equal": true}
{"snapshot_hash_equal": false, "data_manifest_hash_equal": true,
 "first": "edeb3e5d6e035715...", "second": "1572b96e77d3e998..."}
second {'ok': False, 'error': 'ProtocolViolation: run run_repro_A snapshot changed
 (7c1a94e9dacbe0e3 -> 365d282be186e776); cached baselines are invalid'}
```

- **期望**：Merkle root、文件数、文件 SHA-256 不变时，快照身份不变；同一 run 可 resume/report。
- **实际**：`details` 把 `data_manifest_generated_at`（`adapter.py:133`）和 `data_manifest_cache` 路径一起哈希；`full_content_manifest` 每次重建 manifest 都写新的 `generated_at`，所以 `snapshot.manifest_hash` 每次都变。`BoundCandidate.binding_hash` 含 `snapshot_hash`（`schema.py:157-166`），因此 candidate_id 也会变。
- **根因**：把“生成时间/缓存路径”这类运行元数据放进了科学身份。
- **历史影响**：V1.1 的 TSIL 生命周期（discover → freeze → confirm → finalize）在任何跨调用/跨进程场景下都不可执行；历史 `run_20261031_153702` 由旧代码产生，不受影响，但 V1.1 无法复现或复核它。
- **最小修复**：从被哈希的 `details` 中移除 `data_manifest_generated_at` 与 `data_manifest_cache`（保留在非哈希 metadata 中供审计）；回归测试断言两次 `snapshot()` 的 `manifest_hash` 相等，且同一 run 的第二次 `_build_context()` 不抛异常。
- **回归证据**：现有测试无此断言；修复后应新增 `tests/test_tsil_identity_stability.py`。

#### D-03 [历史 B] TSIL 预测 NPZ 的日期/证券索引写反

- **位置**：`predicatelab/domains/tsil/worker.py:246-261`，关键行 `252-254`；上游 `TSIL-main/src/model_backbone_phitp.py` 的 `test_epoch` 中 `preds.index = preds.index.swaplevel()`。
- **触发**：任何 `search.save_predictions: true` 的 TSIL trial，在训练完成后写 NPZ。
- **最小复现**：`repro_D_npz_index.py`；日志 `artifacts/audit_v11/logs/repro_D.log`：

```
upstream preds.index levels: ['datetime', 'instrument']
[(Timestamp('2022-01-04'), '000001.SZ'), ...]
pandas._libs.tslibs.parsing.DateParseError: Unknown datetime string format,
 unable to parse: 000001.SZ
```

- **期望**：`instrument` 数组来自证券层，`date` 数组来自日期层；两种层序都能正确写出。
- **实际**：worker 硬编码 level 0 为 instrument、level 1 为 date；上游 `test_epoch` 已 swaplevel 成 `(datetime, instrument)`，于是 `pd.Timestamp("000001.SZ")` 抛 `DateParseError`。`worker.main` 捕获后写 failed result 并返回 rc=1，整个 trial 失败；即使不抛错，NPZ 的 instrument/date 也会互换。
- **根因**：`_prediction_metrics` 已经用 dtype 检测日期层（`worker.py:121-131`），NPZ 写出却没有复用同一逻辑。
- **历史影响**：V1.1 的 TSIL 探索无法产出任何预测文件；历史 `run_20261031_153702` 的 `save_predictions=False`，因此没有 NPZ 可供复核（历史 final 的 IC 由内存预测计算）。这是 Smoke A/B 的直接阻断项。
- **最小修复**：在 NPZ 块复用 dtype 检测：找到 datetime level 作为 `date`，另一个 level 作为 `instrument`；对单层索引回退到序号。新增测试：用 `(datetime, instrument)` 与 `(instrument, datetime)` 两种 MultiIndex 调用写出函数，断言数组语义。
- **回归证据**：现有测试无 TSIL NPZ 覆盖；修复后新增 `tests/test_tsil_predictions_npz.py`。

#### D-05 [历史 D/G] SearchPolicy 不在实验身份中，改变阈值后 resume 覆盖证据

- **位置**：`predicatelab/core/schema.py:273-288`（`ExperimentProtocol.content_hash` 不含 `SearchPolicy`）；`schema.py:296-314`（SearchPolicy 字段）；`engine.py:284-299`（`context_hash` 不含 policy）；`engine.py:339-366`（`context.json` 写入 policy 但不比较）；`store.py:875-895`（`ON CONFLICT DO UPDATE` 无冲突目标）。
- **触发**：同一 `run_id`，第一次用 `min_effect=1e9`，中断 round；第二次改 `min_effect=-1e9` 后 resume。
- **最小复现**：`repro_G_policy_mutation.py`；日志：

```
run_repro_G
before: [('ev_17ade7484d456118', 'insufficient_evidence', -0.0007134428367078387)]
protocol_hash dff5a17f9216fae1fb344db483ab2bba55603b1ec438108041d3d2dd3c3495c2
context accepted after threshold change: True
[round 0] resuming 1 saved proposals
after : [('ev_17ade7484d456118', 'validated', -0.0007134428367078387)]
same evidence_id: True
context policy min_effect: -1000000000.0
```

- **期望**：科学选择规则（min_effect、min_stability、fdr_alpha、screen/validation folds、top_k、min_fold_coverage、min_seed_agreement）必须进入 experiment identity；同一 evidence 行不得在改变规则后被原地改写。
- **实际**：`protocol_hash` 与 `context_hash` 都不含 policy；`_build_context` 只比较 protocol/snapshot；`record_evidence` 的 upsert 把同一 `evidence_id` 的 status/effect/q_value/created_at 全部覆盖。于是“insufficient → validated”可以在改变阈值后无痕发生。
- **根因**：把科学策略当成了可变的运行参数，而不是预注册的实验身份；证据表的冲突策略允许就地改写。
- **历史影响**：任何“resume 后结论不变”的说法不成立；历史 519 trials/206 evidence 为 legacy，无法证明其阈值与当前一致；V1.1 的证据不可追溯。

#### D-12 [数学] LUSI 的 α 梯度恒为非负，目标漂移到秩 1 项

- **位置**：`TSIL-main/src/model_backbone_phitp.py:97-140`（`WeightedMSELoss.forward`）；`QniverseModel` 的 `alpha`/`tau_hat`；`predicatelab/domains/tsil/dsl.py:212-220`（φ 归一化）。
- **推导**：设 `L = (1/B)Σ e_i (M e)_i`，`M = τ̂ I + (1−τ̂)P`，`τ̂ = σ(α)`。则

```
∂L/∂α = σ'(α) · (1/B) · eᵀ(I − P)e
```

对 native/DSL 谓词，`P = φφᵀ/‖φ‖²`，特征值为 `{1,0,...,0}`，`I−P` 半正定，且

```
eᵀ(I−P)e = ‖e‖² − (φᵀe)²/‖φ‖² ≥ 0
```

因此 `∂L/∂α ≥ 0` 恒成立；梯度下降只会减小 α，τ̂→0，τ→1。所谓“可学习的 τ̂/τ 权衡”是单向棘轮，不是自适应权重。τ→1 时 `L → (1/B)(φᵀe)²/‖φ‖²`：只有残差在 φ 方向的分量被惩罚，MSE 项被消掉，目标退化为秩 1 投影。对常数 φ，P 为均匀矩阵，损失只惩罚 batch 残差均值。
- **最小复现**：`repro_E_lusi_math.py`；日志：

```
e^T I e = 70.0645  e^T P e = 0.8882  I-P PSD check = 69.176276 >= 0
dL/dalpha = 17.294069  (theory: sigmoid'(a)*(V-Pe) = 17.294069)
finite-diff  = 17.3187255859375
tau_hat trajectory: [0.475, 0.2899, 0.1608, 0.0903, 0.0555]
final tau_hat = 0.039451 -> P weight = 0.960549
```

- **期望**：如果论文/方法声称 τ 是学习的权衡参数，梯度应能双向变化；目标在 τ→1 时不应丢失 MSE 项。
- **实际**：梯度符号由 PSD 结构锁死；40 步 Adam 就把 τ̂ 从 0.475 压到 0.039。不同谓词的比较实际上是在比较秩 1 项，而不是“在 MSE 与谓词项之间学习平衡”。
- **根因**：`M = τ̂I + (1−τ̂)P` 的参数化 + `P` 半正定且 `λmax(P) ≤ 1`（Frobenius 归一化保证）使 `I−P` 半正定；这是结构性的，不是数值偶然。
- **历史影响**：历史 final 的 candidate 使用 LUSI、baseline 使用 plain MSE；candidate 未超过 baseline（见 §5.3）。该结果不能被解释为“谓词在学习的权衡下改进了不变损失”；应解释为“在 τ 饱和到 P-only 的目标下没有改进”。
- **最小修复**：这是研究设计决策，不是单行 bug。可选：(a) 固定 τ 并作为超参数报告；(b) 重新参数化使两项权重可双向学习（例如对两项分别学习正权重并加约束/正则）；(c) 至少记录每个 epoch 的 τ，并在报告中明确目标已饱和，禁止把它描述为“学习的权衡”。在修复前，任何“predicate improves the invariant loss”结论都必须降级。
- **回归证据**：数值复现已保存；修复后需新增测试断言 `∂L/∂α` 可正可负（在设计的参数化下），或断言 τ 被固定。

## 4. 数学机制审查

### 4.1 LUSI 损失与梯度

`WeightedMSELoss.forward`（`TSIL-main/src/model_backbone_phitp.py:114-140`）计算：

```
resid = (outputs - targets).reshape(-1, 1)
M = tau_hat * I + tau * P
total = mean(resid * (M @ resid))
```

其中 `P` 由 `phi_fn`/`phi_type` 构造，且在 V1.1 中 `compile_descriptor` 在 `torch.no_grad()` 下运行，因此 ∂P/∂θ 不进入梯度（P 被视为常数）。对 α 的梯度：

```
∂L/∂α = σ'(α) · mean(eᵀ(I−P)e)
```

本节的关键不是“梯度算错”，而是“梯度符号被结构锁死”：

1. native/DSL：`P = φφᵀ/‖φ‖²`，`λ(P) = {1,0,...,0}`；`I−P` PSD；`eᵀ(I−P)e ≥ 0`。
2. composite：`_composite_I_P` 再按 Frobenius 归一化，`λmax(P) ≤ ‖P‖_F = 1`；`I−P` 仍 PSD。
3. cross-corr：`P = ((corr+1)/2)/‖·‖_F`；`corr` 是 `X Xᵀ/T` 的样本相关矩阵，PSD；`(corr+J)/2` PSD；Frobenius 归一化保证 `λmax ≤ 1`；`I−P` PSD。
4. 因此所有谓词族都满足 `∂L/∂α ≥ 0`；α 只能下降，τ̂→0，τ→1。

数值验证（`repro_E_lusi_math.py`）：`V=70.0645`，`eᵀPe=0.8882`，理论梯度 `17.294069`，有限差分 `17.3187256`；40 步 Adam（lr=0.1）后 τ̂ `0.475 → 0.0395`。

**结论**：`τ` 不是“学习的权衡”，而是被结构性驱动到 P-only。τ→1 时目标为 `mean((φᵀe)²)/‖φ‖²`（秩 1 投影），MSE 项消失；对常数 φ 则只惩罚 batch 残差均值。任何“predicate improves the invariant loss under a learned trade-off”的表述都与实际机制不符。这是 P0 级的数学机制问题，且是上游继承的，不是 V1.1 新引入的。

### 4.2 等价退化

- `P` 只依赖 φ 的方向与尺度：φ 与 −φ、cφ 产生同一个 P。`probe_signature` 取 P 的严格上三角（`dsl.py:398-403`），因此去重能识别符号/尺度等价，这一点是正确的。
- 但 `P` 的秩 1 结构意味着：两个谓词只要在 probe batch 上产生相同的样本相似度，就在损失中完全等价；去重签名能覆盖这一点。
- `_normalise_phi` 的常数 fallback 会把退化谓词变成 Φ_ones；这不是“等价退化”的检测，而是把 candidate 静默替换成 control（D-04）。

### 4.3 cross-correlation 的尺度

`get_cross_correlation_I_P`（`TSIL-main/src/custom_phi_constructors.py:1030-1039`）先构造 `corr = X Xᵀ/T`，再 `P=(corr+1)/2`，再按 Frobenius 归一化。数值（`repro_I`）：

```
shape (200,200) trace 1.8879708051681519 fro 0.9999997019767761
min eig -4.6e-08 max eig 0.9743107557296753 PSD? True
e^T P e / e^T e on random e: 0.023934
ratio on top eigenvector: 0.974311
=> e^T(I-P)e can be negative: False
```

- `I−P` 保持 PSD，因此没有负风险/无下界问题；此前“cross-corr 可能导致负风险”的怀疑被**驳回**。
- 但 `trace(P)=1.888`（其他谓词为 1），且 P 不是秩 1；它与 native/DSL 的 P 项尺度/几何不同。跨谓词比较不是 apples-to-apples。P2。

### 4.4 统计实现

`core/stats.py` 的 Newey–West HAC（Bartlett）、moving-block bootstrap、two-sided normal p、Benjamini–Hochberg、fold stability、`pool_fold_series` 去重日期均通过 `test_stats.py` 的已知值/确定性测试。未发现实现级数学错误。问题在于**输入**：selection 与 evaluation 共享数据（D-08/D-10）、freeze 排序错误（D-09）、策略不进入身份（D-05）。因此“统计代码正确”不能推出“统计结论有效”。

`_aggregate` 的 `n_dates = sum(seed n_dates)` 会把同一批日期按 seed 重复计数（历史 evidence 的 `n_dates=958` 是 4 folds × 239/240 的合并，不是 958 个独立日期；多 seed 时会再乘 seed 数）。这不是显著性计算的错误（SE/CI 用配对序列），但报告中的 `n_dates` 容易被误读为独立样本量。P2 记录。

4. 在任何真实 confirmation/final 之前，必须解决 D-08/D-10，并确认 holdout ledger 仍为消费状态。

### 8.2 最高优先级的三个修复动作

1. **修复 D-01 + D-03**：让 TSIL 快照身份跨调用稳定，并让 NPZ 正确识别 `(datetime, instrument)` 层序。没有这两项，V1.1 的 TSIL 生命周期和预测证据都不存在。
